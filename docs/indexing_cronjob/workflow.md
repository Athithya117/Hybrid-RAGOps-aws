### Indexing cronjob(batch data/indexing pipeline)

This document describes the **runtime behavior of the indexing pipeline** as executed by the **Kubernetes CronJob generated by infra scripts**. It is implementation-accurate and follows the real control flow:
**manifest generation/apply → CronJob pod start → indexing_pipeline.py → pre_conversions → router/parsers → index (embed + upsert)**.


```py
apps/index/
├── build_and_push_image.sh           # Builds and pushes the indexer container image to the registry.
├── Dockerfile                        # Defines the runtime image for the indexer CronJob container.
├── indexing_pipeline.py              # Orchestrates the full indexing run: pre-conversion → parsing → indexing.
├── index.py                          # Loads chunks, embeds content, deduplicates, and upserts points into Qdrant.
├── parse_chunk/
│   ├── formats/
│   │   ├── _csv.py                   # Parses CSV files into row- or token-based text chunks.
│   │   ├── _html.py                  # Extracts and cleans HTML or remote web content into text chunks.
│   │   ├── images.py                 # Performs OCR and image-text extraction used by other parsers.
│   │   ├── __init__.py               # Registers available format parsers for router discovery.
│   │   ├── jsonl.py                  # Parses JSONL records into normalized text chunks.
│   │   ├── md.py                     # Parses Markdown files into structured text chunks.
│   │   ├── pdf.py                    # Extracts text, figures, and OCR from PDFs and chunks by page/window.
│   │   ├── _pptx.py                  # Extracts slide text and structure from PPTX files.
│   │   ├── txt.py                    # Normalizes and chunks plain text files.
│   │   └── wav.py                    # Transcribes and chunks audio files into text segments.
│   ├── __init__.py                   # Initializes the parse_chunk package.
│   ├── sample_chunk.py               # A helper file to convert a parquet file into json for readability
│   └── router.py                     # Routes raw files to the correct parser based on type and extension.
├── pre_conversions.py                # Normalizes raw inputs by converting docs, sheets, and audio to canonical formats.
└── requirements.txt                  # Pins Python dependencies required by the indexing pipeline.

```


#### End-to-end behavior

* CronJob runs a **single-process orchestrator** (`indexing_pipeline.py`) inside the pod.
* Pipeline stages:

  1. **Pre-conversions**: normalize raw blobs (docs → PDF, sheets → CSV, audio → WAV), safely move/dedupe blobs, quarantine failures.
  2. **Routing & parsing**: select per-format parser, chunk content, write **parquet+zstd compressed chunks + .manifest.json** atomically.
  3. **Indexing**: load chunks, normalize schema, dedupe against Qdrant, embed (dense/sparse), upsert points with retries.
* **Idempotent by design**: existing manifests, chunk files, and Qdrant point IDs prevent reprocessing unless forced.

---

#### Control-plane flow

* Infra CLI builds CronJob YAML from env-driven config.
* Secrets wired via `secretKeyRef` when present at apply-time; placeholders otherwise.
* Cron triggers Jobs; each Job runs one Pod executing the pipeline command.

---

#### Data-plane guarantees

* **Canonical chunk schema** with strong traceability (`document_id`, `chunk_id`, ranges, source URL).
* **Deterministic point IDs** derived from `chunk_id`.
* **Hybrid indexing** when both dense and sparse embedders are healthy; sparse-only fallback supported.
* **Atomic writes, retries, backoff**, and graceful shutdown handling.

---

#### Supported formats

* PDFs (incl. doc/docx via conversion), text/markdown, HTML/URLs, CSV/sheets, audio, images (OCR).
* Chunking tailored per format (pages, rows, token windows, audio segments).


#### Fault tolerance & safety

* Safe move + atomic uploads prevent partial state.
* Recursive batch splitting on embed failures.
* Deduplication before embedding avoids wasted compute.
* Parsers fail soft and continue processing other files.

---

#### Key runtime knobs (high impact)

* Cron/infra: schedule, concurrency, namespace, managed identity.
* Pre-conv: overwrite flags, OCR behavior.
* Parsing: token window sizes, overlap, encoder.
* Indexing: batch sizes, upsert chunking, Qdrant and embed endpoints.

---

**Net effect:** a deterministic, GitOps-driven, idempotent indexing pipeline with strong traceability, resilient embedding/upsert behavior, and clear separation between infra control plane and runtime data plane.
